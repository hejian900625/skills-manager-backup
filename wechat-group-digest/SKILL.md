# 群刊编辑部：群聊数据 → AI 提炼 → 单文件网页

> **三层结构导读**（2026-09-09 定稿）：
> **L1 核心方法论**——跨群不变的地基：铁律、管线、通读、精细化、大群模式。
> **L2 内容拆解与结构**——按群适配的灵魂：群型识别→领域假设、digest.json schema、各类写作规范。
> **L3 Web 呈现**——组件化渲染：脚本单真源、美学基准、可选版块、性能基线。
> 改技能前先判断改动落在哪一层：方法论层要慎重（影响所有群），适配层鼓励因地制宜，呈现层改脚本即可。

## 快速上手（新群从零到刊）

> 本技能按"程序与数据分离"发布：脚本**不写死数据库路径**，所有命令都要显式带 `--db`。
> `DB` = 你的 wechat_stats.db 路径——**该库由 wechat-group-export 的 `--sqlite` 产出**，没有就先跑那个技能。
> 切片默认落在 `<db目录>/.workbuddy/digest_src/`；成品 HTML 默认落在 **`<db目录>/outputs/rendered/`**（2026-09-09 起与提取文档分目录存放，不再放 `.workbuddy/`），无需另设。

```bash
DB="D:/微信群导出/wechat_stats.db"     # ← 换成你的库路径

# 1. 切片（若此步能唯一命中群名，说明库里已有该群）
python scripts/export_digest_src.py --group 群名片段 --db "$DB"

# 2~4. AI 逐月通读切片 → 判群型、定领域假设（L2）→ 写编辑部稿 insights/<群>_digest.json

# 5. 渲染（缺 digest.json 会拒渲染——铁律：页面必须经 AI 提炼）
python scripts/render_group_page.py --group 群名片段 --db "$DB"
```

自检：数字对基准、章节/条目/语录计数、JS 尾部完整、对照 L3 性能基线 → present_files。

## 与 wechat-group-export 的分工（边界）

| | export（采矿队） | digest（本技能，编辑部） |
|---|---|---|
| 职责 | 加密库 → 可信数据（MD + SQLite） | 可信数据 → 群刊页面 |
| 变更节奏 | 微信版本变了才动 | 品味迭代，常动 |

**不互相塞**：导出技能不学排版，本技能不碰解密。

# L1 · 核心方法论（跨群不变）

## 铁律（先读）

1. **页面必须经 AI 提炼，不能纯自动生成**——渲染脚本强制校验 `<workdir>\<群>_digest.json`，缺失即拒渲染。规则生成只配做统计，配不出"编辑部"。
2. **无原文流水账**：逐条展示原文没有意义；原文只以"手册条目内的引文"形态出现。
3. **统计瘦身**：四格数字 + 日曲线 + Top10 榜即封顶。热力图/类型占比/参与分层这类"看着专业读者不看"的，砍。
4. 交付前**数字必须与库内基准对照**（`groups.msg_count`、发言人数 SQL），页面数字句句可查是本技能的公信力底线。

## 管线四步（每群复用）

```bash
# ① 切片：全量聊天文本按月落盘（AI 通读的输入）
python scripts/export_digest_src.py --group 群名片段 [--db 路径]
#    → <db目录>/.workbuddy/digest_src/<群名安全化>/YYYY-MM.txt

# ② AI 通读：逐月 Read 切片，按月记要点（切片就是为了不爆上下文；
#    127 群这类大群 = 切片更多轮，机制不变）

# ②b 领域定向挖掘（精细化关键，不可省）：按问题域派子 Agent 回原文重挖，
#    Grep 定位 + Read 精读，产出速查表+条目+存疑清单。
#    领域清单由群型识别→领域假设得出（见 L2），**不许写死**
#    跳过这步 → 产出必然是编年史，见「精细化」节
#
# ③ 编辑部稿：AI 写 insights/<群名安全化>_digest.json（schema 见 L2）

# ④ 渲染：缺 digest.json 直接报错拒渲染
python scripts/render_group_page.py --group 群名片段 [--db 路径] [--out x.html]
#    → <db目录>/<群名安全化>_群刊.html（单文件，双击即看）
```

群名安全化：`re.sub(r"[^\w\u4e00-\u9fff-]+", "_", name).strip("_")`（emoji 群名如 ⚒️ 会转成下划线，必须 strip）。

## 通读方法

切片按月逐个 Read（每月一文件），边读边记：谁在反复出现（核心人物画像）、哪些话题吵起来了（手册候选）、哪些话值得原样留下（金句候选）。读完全部切片再动笔——主题结构是读完才长出来的，别边读边写。

## 精细化：从「编年史」到「实战手册」（决定本技能水平）

### 叙事陷阱（最常见的失败模式）

按**时间流水**通读切片 → 产出必然是编年史（"建群第一夜""XX 风波""某人十天攻坚"）。读者看完知道发生过什么，**带不走任何可操作的东西**。

判据：随机抽一条问"读者能照着做吗？"——答不上来就是不合格。真正有价值的群刊是**知识库**：按问题域组织，每条能查、能用、能验证。

### ②b 领域定向挖掘

通读之后、写稿之前，按**问题域**（不是按时间）派 N 个子 Agent 回原文重挖。**领域清单来自 L2 的"群型识别→领域假设"，每群各不相同**；子 Agent 的手段是共通的：

- **手段**：Grep 在切片目录搜领域关键词（`-C 2` 拿上下文）→ Read 命中密集段落读全 → 输出**速查表 + 知识条目 + 存疑清单**
- **存疑清单必收**：没查实的线索交回主编辑回查——这是防 AI 编造的闸门
- 主编辑汇读全部领域产出后再写 digest.json
- **假设不成立就砍**：某领域挖不出 3 条可用条目，砍掉，不硬凑

### 出稿自检清单

- [ ] 随机抽 3 条，能不能照着做？
- [ ] 标签里有没有形容词？图谱节点是可复用的概念/实体吗？
- [ ] 速查表有没有把"未确认"写成确定事实？
- [ ] 数字对得上库账基准吗？（对照《数据结构说明.md》）

## 大群模式：分片 map-reduce 通读（127 群 21765 条实测）

切片总量 >100KB（单模型上下文装不下全量原文）时，**主对话不直接通读**，改用流水线：

1. **切片**：`wc -l` 各月文件，按 ~100KB/片拆行段（约 1300~1800 行/片）
2. **map**：派子 Agent 并行精读，每片一份结构化笔记（≤1200 字：主题线索 3~6 条带日期参与者+重写细节／金句候选 2~4 条原文摘录／时间线事件／群生态一句话）。**纪律：每片全量读不许跳行；prompt 必须自包含**（文件绝对路径+行段+格式说明+群背景+"截断属正常"）
3. **分批**：每批 4 个并行，批间检查笔记质量再放下一批（防并发限流，留质量卡点）
4. **reduce**：主对话汇读全部笔记（16 份约 2 万字，装得下），亲自写 digest.json——手册结构、金句取舍、尾声定调由主编辑统一把关

铁律不破：每个字都被 AI 读过（子 Agent 也是 AI）；但品味必须主编辑自己拿——子笔记给料，digest 的大纲与判断是主编辑的活。

# L2 · 内容拆解与结构（按群适配）

## 群型识别 → 领域假设（适配核心，取代写死的领域清单）

**领域清单不许写死。** 127 群实证出的"故障/成本/配置/工具/项目"只是**技术研讨型群的一个实例**，换个群照抄就是刻舟求剑。正确姿势是先判型、再假设：

**第一步 · 群型识别**（汇读通读笔记时顺带完成）：

| 群型 | 识别特征 | 领域假设方向（示例，非模板） |
|---|---|---|
| 技术研讨型 | 报错/参数/版本号高频 | 故障解法 / 配置环境 / 工具选型 / 方法论 |
| 资源分享型 | 链接/文件/求资源高频 | 资源类目 / 获取渠道 / 使用评价 / 避坑 |
| 行业协作型 | 业务词/对接/排期高频 | 业务流程 / 术语表 / 协作规矩 / 真实案例 |
| 兴趣交流型 | 作品/晒图/活动高频 | 入门路径 / 技巧经验 / 装备清单 / 活动纪要 |
| 综合闲聊型 | 话题跳脱、无主线 | themes 可瘦身为 2~3 章"聊得最透的几件事"，重心放群像+语录+时间胶囊 |

混合型按主导特征定主轴，允许跨型取 2~3 个方向。

**第二步 · 领域假设**：主编辑从通读笔记提炼 **3~5 个这个群真实存在**的问题域，每个写成一行：`域名｜挖什么｜Grep 关键词（3~6 个）`。这份清单注入子 Agent prompt（大群模式）或直接作为自己的重挖路线（小群）。

**第三步 · 回挖验证**：按 L1「②b 领域定向挖掘」执行；挖不出料的领域砍掉，临场冒出的新领域允许追加。

## digest.json schema

```json
{
 "group": "群名", "digest_version": "YYYY-MM-DD", "editor": "提炼者说明",
 "themes": [{"id":"t1","title":"主题名","meta":"Chapter 01 · EN",
   "lead":"本章导语（2~3句，说清这一章装什么）",
   "table":{"caption":"速查表标题","cols":["列1","列2"],"rows":[["值","值"]]},
   "items":[{"no":1,"title":"条目标题(写成结论或做法,≤18字)","tag":["#一级领域","#二级对象"],
             "body_html":"<ul><li>要点式知识，含 <code>路径/参数</code>、<b>数字</b></li></ul>",
             "source":"07-14 ~ 07-17","confidence":"群内共识/少数人验证/有争议"}]}],
 "quotes": [{"text":"金句≤40字","who":"昵称","date":"07-16"}],
 "epilogue_html": "<p>尾声综述：全景概括 + 「只带走三句话」式收束</p>",
 "personas": [{"nick":"昵称","msgs":1234,"tag":"2~4字标签","verdict":"人物判词≤22字，有画面有观点"}],
 "personas_note": "群像说明（如：发言榜某位是客服机器人不进群像）",
 "capsules": [{"label":"4字标签如 第一句话","date":"MM-DD HH:MM 或时间段","who":"相关人/数据",
               "text":"一句封存的时刻，首尾对照/最长消息/深夜灯火/峰值日等"}],
 "graph": {"groups": {"g1": {"label":"分组名","color":"#A63D24"}},
           "nodes": [{"id":"x","label":"概念或实体","w":1~5,"g":"g1"}],
           "edges": [{"a":"x","b":"y","rel":"导致|解法|依赖|对比|替代|案例"}]}
}
```

**可选字段**：`table`/`confidence`/`personas`/`personas_note`/`capsules`/`graph`/`exclude` 缺省时对应版块自动跳过，老 digest 照常渲染——**版块取舍本身就是适配的一部分**（闲聊群可以没有图谱和速查表）。

> **章节序号不用写**：`壹/贰/叁…` 由渲染器按「群像=壹 → 主题依次往后排 → 时间胶囊 → 语录」动态生成，`themes[].cn` **写了也不读**（老稿里的 `cn` 可留可删）。中文序号只有十个，超出自动回退成阿拉伯数字。
> **胶囊 `text_html` 优先**：`capsules[]` 可填 `text`（纯文本，会转义）或 `text_html`（受控 HTML，可加 `<b>` 强调）；**两者都填时用 `text_html`**，但二选一必填其一，否则校验报错。

> **`exclude`**：官方客服/机器人账号的**完整昵称**列表（如 `["福利派送媛儿-小新（服务时间为工作日9:00-18:00）"]`）。填了就从发言榜剔除并顺延补位，页面会注明"已剔除 N 个官方/机器人账号"。**昵称必须查名册取全**（带括号后缀的常有），写不全等于没剔除。

## 条目写作五要素

1. **重写，不摘抄**：把几天讨论消化成一个可独立阅读的知识点；原文只有金句级引语才进正文。
2. **细节是生命线**：插件名、参数、报错码、数字结论必须保留；"大家讨论了很多"这类空话全删。
3. **每条带出处日期段**（`source: "07-14 ~ 07-17"`）——读者想较真能回原文查。
4. **按问题域聚类，不按时间**：章节 = 领域手册（领域来自本群的领域假设），叙事元素集中在时间胶囊与语录，**不要把手册章写成"XX 事件始末"**。
5. **争议话题写双方立场**，不替群下结论；"观点与共识"章只收真共识。

**在此之上三条升级**：

1. **写成结论或做法**，不写成故事名：`回退版本：覆盖安装，绝不卸载` 合格 / `4.20.4 事故始末` 不合格
2. **正文用 `<ul><li>` 要点化**：一条一要点，3~5 条，每条带数字/路径/版本/操作顺序
3. **`confidence` 必填**：群内共识 / 少数人验证 / 有争议（有争议写双方立场，不替群下结论）

## 速查表规范（theme.table 字段）

- 每章挂一张，列 = 可对照维度（现象/原因/解法/代价/出处——列名跟随本群领域假设灵活定）
- 7~15 行，每行能独立照做；数字、路径、版本号必须来自原文
- **查不到就写"未确认"，绝不许编**——宁缺毋滥是速查表的生命线

## 两级标签体系

- 一级 = 领域（来自本群领域假设，如技术群的 `#故障` `#配置` `#方法论`）
- 二级 = 对象（具体到实体，如 `#自动更新` `#models.json` `#多Agent`）
- **禁区**：形容词标签（`[群史起点]` `[信任危机]` `[收藏向]`）——不产生信息、不能检索

## 金句标准

带**观点/态度/总结性**的短句（≤40 字），如「附件是附件，笔记是笔记」。技术标题不算（"File Cleaner 大概思路"是标题不是金句）；规则捞不出金句，必须读懂上下文再挑。每条注明说话人与日期。

## 人物判词规范

- **原料**：用脚本把 **Top10** 每人的全部文本消息导出成单人文件（参照 `scripts/make_persona_src.py`，该脚本取 Top10 且**不做 exclude 剔除**），派子 Agent 每人全量精读后交回判词+依据；主编辑只做选词微调。**判词必须读原文写，不许从主题手册倒推。**（注：页面群像榜也是 Top10，但会先按 `exclude` 剔除机器人再顺延补位——两处口径不同，别混为一谈）
- **判词标准**：≤22 字、有画面有观点（"点错一次升级，把自己焊成了群里最勤的活字典"合格；"很热心的大佬"不合格）。
- **`who` 用原文昵称**：注意昵称可能是纯符号（如「。」）或纯 wxid——先用 SQL 查名册确认身份再动笔。

## 时间胶囊规范

高光锚点由脚本自动捞（首末消息/最长消息/深夜消息/峰值日/每人首末句，见 `_anchors.md`），AI 通读锚点后挑选 5~7 条封存：**第一次与最后一次**（首句→末句的成长弧线最戳人）、**最长的一条**、**深夜灯火**、**最疯狂的一天**。每条一句点评，不堆数据。

## 话题地图数据规范

- **数据全由编辑部稿提供**（digest.graph）：节点 = **概念或实体**（不是事件名）；连线 = 两个节点间真实存在的关系，**每条边必须标 rel**。
- **节点要能复用**：`models.json`、`.workbuddy`、缓存命中 这类可复用的概念/实体才算好节点；「XX 风波」这种一次性事件名没有复用价值（它只该出现在条目里）。
- **rel 六种**：`导致`（朱砂实线 #A63D24）/ `解法`（墨绿实线 #3D5C4C）/ `替代`（墨绿虚线）/ `案例`（暖灰点线 #8C8272）；`依赖` 与 `对比` **没有专门配色**，落默认灰虚线（#B3A995）。实际只有 4 种配色，别按"六种各有色"去验收。悬停显示「A —导致→ B」。
- 节点 20~35 个、分 **3 组**配色为宜（>3 组显得杂）；边数 ≈ 节点数；禁止堆砌标签凑数。**小群按实际话题数下浮**：消息量只有几百条的群硬凑 20+ 节点，会把一次性事件顶上来当节点，按真实可复用概念给到 15~20 即可（Creaibo 71 条取 17 节点，实测合理）。
- 无图谱价值的小群/闲聊群：**直接不给 graph 字段**，渲染自动跳过该版块。

# L3 · Web 呈现（组件化渲染）

## 渲染脚本（单真源）

- 全部 CSS/JS 内嵌在 `scripts/render_group_page.py`，改样式改脚本，**不另立样式文件**。
- 数据驱动版块：digest 里有什么字段就渲染什么版块，缺省自动跳过；渲染脚本永远不做"必须齐活"的假设。
- d3-force v3（含 dispatch/quadtree/timer，17.5KB UMD，ISC 协议）存于 `scripts/vendor/d3-force.min.js`，**仅当有图谱时按需内联**（保持单文件离线）。

## 美学基准（豆包 chat-digest 式纸质札记风）

- **视觉**：米黄纸底 `#F7F4EC` + 卡片 `#FFFEFB`、**标题宋体**（Noto Serif SC/SimSun）、**正文一律系统字体栈** `-apple-system,BlinkMacSystemFont,"Segoe UI","PingFang SC","Microsoft YaHei",Arial`（r5 定案：只有标题用衬线，内容不衬线，避免"装饰感"压过可读性）。朱砂红 `#A63D24` 只用于**强调**（印章/峰值/因果边/争议标注），其余一律中性灰调；标签 chip 用浅灰底深灰字，不用彩色。
- **配色纪律**：同一屏出现的强调色 ≤ 2 种；图谱分组 ≤ 3 色且降饱和（墨绿 `#3D5C4C` / 赭石 `#A6743B` / 青灰 `#5B7385`）。加新色前先问：这个颜色传达信息吗？不传达就是噪音。
- **骨架**（全部版块可缺省）：卷首（kicker + 大标题 + 印章 + 导语 + 四格数字 + 日曲线）→ 粘性目录（滚动高亮）→ 话题地图（可选）→ 群像（Top10 表 + 人物判词卡，可选）→ **领域手册章节（导语 + 速查表 + 条目，可选）** → 时间胶囊（可选）→ 语录卡 → 深绿尾声卡 → footer（写明数据源与提炼方式）。周时间轴已删（用户定案）。
- **⭐ footer 引流条（2026-09-09 用户定案，永久固化，每刊必有）**：footer 顶部固定一条 `.f-flash`——大字「你是群里最**靓**的仔！」（"靓"字朱砂），小字两行 CNB 下载地址：群导出 skill `https://cnb.cool/fzz198479/wechat-group-export`、群刊 skill `https://cnb.cool/fzz198479/wechat-group-digest`。已内嵌在渲染脚本 footer 模板中，任何群重渲染自动带出；改动下载地址只改脚本，不逐刊手补。
- **动效**：IntersectionObserver 渐入（.reveal）、话题地图力导向自组织 + 拖拽、`prefers-reduced-motion` 降级（含地图不自动播放动画，但拖拽仍可用）。
- 参照物：豆包 chat-digest 页（米黄纸质感+编辑部条目卡）——借鉴其形，数据用我们可信的。

## 话题地图交互规范（d3-force，禁止手搓物理）

- 页面载入 d3 自组织收敛后静止；**节点可拖拽**（d3 标准模式：`fx/fy` 固定 + `alphaTarget(0.3)` 保能量，松手归零），邻居被 forceLink 自然牵动；悬停高亮邻居与相连边。数据经 `<script type="application/json" id="graph-data">` 注入，Python 端只算确定性初始布局。
- **调参要点（实测）**：`forceCenter` 只平移质心**不约束边界**，须用 `forceX/forceY` 软弹簧 + tick 回调内 clamp（d3 官方推荐）双保险；当前参数 link distance=165/strength=0.6、charge=-1500、forceX/forceY strength=0.08/0.09、collide r+14。
- **改参数必须数值验证**：用 node vm 跑 300 tick 验证无 NaN、不出界、拖拽邻居有跟随量，别靠肉眼。

## 性能基线与回归验证（2026-09-09 固化）

| 指标 | 基线 | 超标处理 |
|---|---|---|
| 渲染耗时 | ≤1s/群（实测 维客 0.16s / 127群 0.38s） | 查是否误加了重计算（Python 端布局仅做初始摆位） |
| 单文件体积 | ≤120KB（127 群实测 114KB） | 查是否重复内嵌 vendor 或死 CSS 回潮 |
| 一致性回归 | 同 digest 重渲染，剥掉页脚时间戳行后应与基线逐行一致 | diff 出别的差异 = 动了模板，需人工确认视觉 |

回归流程：改渲染脚本后，用 127 群重渲染一次 → 剥页脚时间戳 → 与改动前产物 diff → 仅预期差异才算过。

# 踩坑实录（历次迭代血泪，动手前扫一遍）

| # | 坑 | 解法 |
|---|---|---|
| 1 | 同一文件多个 Edit 并行发出会互相覆盖（后写者基于旧内容冲掉先写者） | 同文件编辑必须**串行** |
| 2 | emoji 群名（⚒️=U+2692+U+FE0F）转文件名出头导下划线 | `re.sub(...).strip("_")` |
| 3 | Python f-string 内嵌 CSS/JS：`{{}}` 转义、孤引号跨行拼接极易语法错 | 生成后必须 grep 抽查标签计数与 JS 尾部；`py_compile` 先过一遍 |
| 4 | 微信复合消息类型是大数值 flag（244813135921 等），content 带 `[类型X] ` 前缀 | 正则剥前缀再用；空壳显示类型占位 |
| 5 | 规则版"长文首句当金句"质量崩（标题混进语录） | 金句必须 AI 挑，规则只配做统计 |
| 6 | digest 里 body_html 是受控 HTML，esc 会破坏标签 | body_html 走原文注入（写作时就保证安全），title/who/date 走 esc |
| 7 | 页脚嵌"生成：时间戳"，两次渲染哈希必不同 | 验证渲染一致性时先剥掉页脚时间行再比对，或逐行 diff 后确认仅时间戳差异 |
| 8 | 多群切片默认同目录，`YYYY-MM.txt` 互相覆盖（127 群导出险些冲掉维客切片缓存） | 默认输出已改为 `digest_src/<群名安全化>/` 按群分目录；旧版单层目录产物需手动归位 |
| 9 | Top10 表格曾直接渲染 messages.sender（内部 username/wxid），用户一眼看穿"这不是昵称" | 群友名一律经 members 表 映射昵称（fallback 原值）；自检时把表格里的名字逐个人眼过一遍，别只数行数 |
| 10 | **叙事陷阱**：只按时间流水通读 → 产出编年史，读者带不走任何可操作的东西；标签沦为形容词、图谱节点成事件名 | 通读后**必须加一步领域定向挖掘**（领域来自群型识别→领域假设，见 L2），条目写成"问题-解法"、正文 `<ul><li>` 要点化、两级标签、每章挂速查表。判据：随机抽一条问"能照着做吗" |
| 11 | 剔除机器人时按短昵称写 exclude（"福利派送媛儿-小新"），名册里真实昵称带括号后缀，结果没剔除成功 | exclude 一律查 `members` 表取**完整昵称**；渲染后自检发言榜末尾几行确认无客服/机器人 |
| 12 | 自研力导向物理（手搓弹簧+alpha 衰减），联动体感差、参数靠猜，用户点破"有成熟组件" | 图物理一律用 d3-force（vendor 内嵌）；换库前先 node vm 验证 UMD 自包含性 + 300 tick 数值验证；`forceCenter` 不约束边界，须 forceX/Y+clamp |
| 13 | 领域清单写死在技能里（"故障/成本/配置/工具/项目"五领域），换群即僵死 | L2「群型识别→领域假设」：先判型、再假设、回挖验证、不成立就砍 |
